# SysCore Performance Baselines

This directory contains stored performance baselines used by the CI regression suite (`scripts/compare_benchmarks.py`) to validate performance integrity on each pull request and commit.

## Platform-Specific Baselines

SysCore performance baselines are partitioned by operating system target:
- `macos.json`: Baseline measurements generated on macOS (Darwin arm64/x86_64).
- `linux.json`: Baseline measurements generated on Linux (Ubuntu / glibc kernel futex).
- `baseline.json`: Legacy baseline maintained for fallback compatibility.

### Why Baselines Are Platform-Specific

1. **Kernel Primitive Semantics**:
   - macOS synchronization primitives utilize Darwin Mach semaphores and `os_unfair_lock`, whereas Linux uses kernel `futex` wait/wake syscalls.
2. **Virtual Memory Allocation (`mmap`)**:
   - Linux VMA page fault handling and page table entry (PTE) allocation differ significantly from macOS Mach VM page mapping latency.
3. **Thread Scheduling & Virtualization**:
   - Multi-threaded contention benchmarks (e.g. 4-thread and 8-thread semaphore/mutex contention) exhibit different scheduling latency characteristics on Linux 2-vCPU cloud runners compared to native macOS hardware.

## Baseline Generation & Maintenance Protocol

### How to Regenerate Baselines

To regenerate a platform-specific baseline on an actual target environment:

```bash
# 1. Clean build the release binary suite
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build

# 2. Run multi-pass benchmark collection (3-pass representative median aggregation)
python3 scripts/run_benchmarks.py --build-dir build --output build/results.json --runs 3

# 3. Update the stored baseline file for your operating system
# On macOS:
python3 scripts/compare_benchmarks.py --current build/results.json --baseline benchmarks/baselines/macos.json --update-baseline

# On Linux:
python3 scripts/compare_benchmarks.py --current build/results.json --baseline benchmarks/baselines/linux.json --update-baseline
```

### Critical Rules for Developers

1. **Do NOT Editing Baselines Manually**:
   - Baselines must reflect actual empirical measurements generated by running `scripts/run_benchmarks.py --runs 3`. Never manually edit baseline numbers to hide performance regressions or bypass CI checks.
2. **Identical Benchmark Configurations**:
   - All 29 benchmark configuration names, warmup iterations, and measured iteration counts must remain identical across all platform baselines (`linux.json` and `macos.json`).
3. **50% Regression Threshold**:
   - The global regression checker enforces a strict 50% threshold on latency increases and throughput drops against the target platform baseline.
